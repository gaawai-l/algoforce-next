# A2–A5 架构验收契约

2026-09-26，用户授权推进到 A5。此范围承接架构阶段，不提前宣称完整策略规格或真实券商已实现。

## A2 数据底座

标准化数据包含来源、交易场所、标的身份、基础/计价币种、价格精度、时区、交易时段、周期、开收盘时间、OHLCV、形成/收盘状态。首期接入加密现货 24/7 数据：确定性 fixture 与 Binance 官方公开接口；美股交易日历、复权、moomoo 接口另行验收。

Python 拥有独立 SQLite；通过版本化、带校验和的增量迁移建表，不直接读写 Wealthfolio 数据库。原始批次、K 线修订、观察记录、任务和分析快照分开保存。相同内容重复导入不产生新修订；数值修订追加版本，保留原值、来源和取得时间。缺失成交量保持 null，价格使用十进制字符串持久化。

## A3 计算与任务框架

统一纯计算入口输入已选择的数据版本、规则参数、行情截止时间和知识截止时间，输出数据质量、指标序列、结构参考与来源。用 SMA 与此前 N 根 high/low 作为验证计算，不生成交易信号。预热不足、缺口、形成中 K 线、过期数据具有明确状态。

实时与回放调用同一入口。默认查询只使用取得时间不晚于知识截止、收盘时间不晚于行情截止的数据。回放若使用今天取得的历史数据，明确标为 retrospective，不冒充当年实际可得的数据。快照固定输入修订 ID、参数、引擎版本和哈希；数据修订不能改写已保存的快照。

持久化任务具备幂等请求键、原子领取、租约、有限重试和摄取后 checkpoint。进程异常退出后，租约过期即可继续，已取得的批次无需重新下载。按所选周期收盘安排定时刷新，用户显式启用；服务重启保留设置并合并错过的刷新，不无限补队列。

## A4 应用接口

在 Wealthfolio 同一导航内提供数据源/标的、方法 tabs、周期、一张 K 线图和当前方法详情。默认 Key levels 验证数据链路；TD Sequential 与 Fibonacci 标记尚未接入此正式引擎，保留原型供后续功能设计。提供手动刷新、任务进度、定时刷新、已保存快照、回放截止、规则窗口、数据来源和错误提示。

前后端类型来自 OpenAPI，客户端验证响应版本与结构。界面将模拟数据、公开行情、历史回放、过期缓存和不可用数据分开；公开源失败不切换到 fixture。Python 失联时撤下连接成功状态并停止将旧结果表示为当前结果。

## A5 验收

在已确认的公开存储接口、统一计算接口、任务接口和 HTTP/宿主界面上验证：

- fixture 和公开数据 Adapter 通过相同摄取/计算路径。
- 重复导入、重复任务、数据修订、形成中数据、缺失值、缺口均有独立预期样本。
- 行情截止与知识截止隔离，无未来数据，实时/回放结果一致。
- 可恢复失败、重试耗尽、租约失效、checkpoint 后重启；旧快照保持可读。
- 数据库从旧 schema 升级、迁移重复执行、服务重新启动不丢数据。
- 实际浏览器检查刷新、周期/方法切换、回放、错误恢复和窄屏。
- 基准：本机 1,000 根数据的摄取加分析目标小于 2 秒；记录环境、数据量和实测结果。网络延迟单列。
- 类型、测试、构建和两轴 code-review 通过。远端 CI 是否实际运行单独说明。

真实账户、股票日历、Tauri 打包、远程认证部署和完整 DeMark/Regime/Breakout 算法不是 A5 架构验收的替代品，也不计入本轮已完成能力。

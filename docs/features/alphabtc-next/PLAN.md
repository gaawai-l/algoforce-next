# AlphaBTC 6.2 之后部分的复刻计划（2026-09-28）

依据：AlphaBTC 主站 v2.95.0 登录后的客户端脚本，以及已核对的[周期规则](../../../research/alphabtc-regime-cycle-source-2026-09-28.md)。需要作者回答的问题见 [QUESTIONS](QUESTIONS.md)。

## 1. 各部分现状与结论

| 部分 | AlphaBTC 里怎么来的 | 能否现在做 |
|---|---|---|
| ④ 链上六态 + 0–100 周期指数 | bitview 公开日线，规则已从源码摸清，本地复算与看板一致 | **能**，规则完整 |
| ④ 五档 / ⑤ 形态选择 | 纯手动，默认"初期突破 / 突破衰减" | 能做成手动选择，等 UI 阶段 |

| 6.2 暴涨监测器 | 预警档位、60/40、四个模块全部写死或手动 | **不能自动**，缺定义（问题 1–5） |
| 6.2 阴跌加速监测器 | 指标"STH 盈利供应占比"，数值与阈值写死 | 指标值**能**从 bitview 算；阈值口径待确认（问题 6–8） |
| 6.2 交易主题（加息预期等） | 静态文案；FOMC 日期、利差、概率都"待接数据" | FOMC 倒计时、10Y−1Y 利差**能**接；其余待定义（问题 9–10） |
| ⑥ 期权策略 / ⑦ 风控移仓 | 由手动形态查表给默认动作，可手动改；Regime 不参与 | 能照搬静态表；语义待确认（问题 11–14） |
| ⑧ 策略置信度 | 作者给的回测表，写死 | 能用自己的引擎复算，先反推胜率定义（问题 15–16） |

## 2. 执行顺序

每一项都是：后端计算 + 只读接口 + 测试 + 页面上一个核对区块（与 DeMark Regime 核对区块同一形式，正式 UI 另议）。缺数据或过期时显示不可用，不用默认值冒充。

### P1 链上六态 + 周期指数

- **数据：**bitview.space 公开日线（无需鉴权），按 Bitcoin Research Kit 的序列名取数。
- **计算：**照[周期规则](../../../research/alphabtc-regime-cycle-source-2026-09-28.md) §3、§4：
  - 六态：三条成本线的排序加死区滞回（默认 5×）；
  - 当前状态、本段天数、历史切换次数、同状态各段的统计；
  - 四成分百分位指数、综合值、1/7/30/90 日变化和所处区间。
- **验收：**用固定的历史数据做测试夹具，结果与 09-27 看板的值一致：Breakout 第 5 天、42 次切换；A 45 / B 68 / C 46 / D 20，综合 45。
- **新鲜度：**最新日线早于前一 UTC 日视为过期；取数失败视为不可用。

### P2 阴跌加速：短线抛压指标

- **数据：**bitview `sth_supply_in_profit / sth_supply`，每日一个值。
- **显示：**当前值和近 30 日走势。预警线 84.5%、确认线 75% 按作者给的数值暂时写死，并标注"阈值待作者确认"。
- **暂不做：**σ 的计算，等问题 7 的答案。

### P3 加息预期主题的可接数据

- **FOMC：**从美联储官网日历解析下一次会议日期，计算倒计时。
- **利差：**从 FRED 的公开 CSV 取 DGS10 − DGS1，标明数据日期（FRED 日数据有 1 个交易日延迟）。
- **暂不做：**CPI/PPI 与预期的比较、加息概率，等问题 9 的答案。

### P4 回测复现（⑧）

- **复算：**用本地 DeMark 引擎和 Bybit 现货历史 K 线，对 1h、4h、1d 的 Buy 13（卖 Put）和 Sell 13（卖 Call）两类信号做回测。
- **反推口径：**两种胜率口径都算：
  - 持有期内收盘从未穿过 Risk Level；
  - 持有期末收盘在 Risk Level 之外。
- **对照：**把结果和作者的表比较，反推他用的是哪种口径。先出研究报告，不进产品；等问题 15–16 确认后再决定是否上页面。

### P5 手动部分（④ 五档、⑤ 形态、⑥ 期权、⑦ 风控）

- 照搬静态表和手动选择，放到正式 UI 阶段一起做。

# 订单费用后台同步验收

日期：2026-09-27。目标不变：完整 moomoo SG 只读接入、Wheel账本、组合风险；本轮补齐费用分批实现，真实账户验收仍未完成。

## 行为

- POST `/portfolio/sync` 返回202与持久任务ID，按账户显式请求，不阻塞页面等待所有费用。
- 首先取得并保存持仓/现金/订单/成交/选定范围现金流水；随后对成交涉及的去重order_id，每20个一批查询费用。
- 费用请求间隔至少3.1秒，同账户基础采集至少31秒。配额记录、任务cursor、已取得费用和缺失ID保存在独立portfolio数据库，重启继续。
- 每次SDK子进程50秒超时；任务90秒租约、每阶段最多3次尝试。旧worker丢失lease后不能发布结果。
- 原始capture与任务cursor同事务提交；发布失败不会先跳过该批费用。
- 漏返、空值、无效fee_amount与缺少order_id不会变成零；任务为partial，coverage列出pending/missing与unknown identity。
- `snapshot_observed_at`固定基础账户快照时间；`captured_at`记录最新费用取得。隔日补费用不会将旧现金和持仓表示为新鲜。旧checkpoint缺少该字段时，恢复前先冻结旧取得时间。
- 相同幂等键返回同一任务；不同键遇到同账户活动任务明确冲突，不作无法持久重试的临时别名。

Standards审查发现并修复活动任务幂等键别名丢失；Spec审查发现并修复费用刷新掩盖旧快照及旧checkpoint兼容问题；两轴均已复核关闭，无剩余本轮阻塞。此前旧capture/event新增默认字段导致重复导入不兼容也已增加回归并修正为模型语义比较。

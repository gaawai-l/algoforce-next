## 6. 实现中的裁定（摘要，完整内容见 SDD 台账）

- **P5-X1**：`_derive` 的已收盘日 C 由本轮开始的 `at` 算出；重派生用已存的 `computed_at`。
- **P5-X3**：`WHEELHOUSE_RULES` 中的空项（如 `O1,`）会让服务启动失败。
- **P5-X8**：所有桶宽共用一个 F。如果某一种快照长期缺失，O1 下整个 cost-basis 都不可用，原因码为 `urpd_not_final`，日志会列出缺的是哪几种快照。
- **P5-X9**：
  - 整小时缺失的时间戳按缺口处理，不当作没出块：腿为 null，xgap 加 1，并报 `hour_gap`；
  - 窗口开头连续的没出块小时丢掉；
  - 沿用值只取上一个时钟小时。
- **P5-X10**：O2 的回看长度为 2881。计划写的 2880 会让最早显示的小时只有 719 个样本。
- **P5-X12/13**：O2 下，窗口被回看截短的小时，阈值为 null，不用较少的样本凑数。
- **P5-X14**：旧的永续载荷（含 `n_all`）在首轮重新派生之前返回 500，按 P5-R10 不做兼容。
- **P5-X15**：O6 下 `collecting:<天数>` 的天数取参考块 R 的清算样本数，与 `collecting` 标志出自同一个样本。

## 7. 已知限制与观察

- **O1 下没有已收盘的完整日**：周期视图回退为 `brk_unavailable`，与 v1 没有任何完整行时一样。实际几乎不会发生。
- **重派生的锚点**：重派生用已存的 `computed_at`（即本轮结束时刻），正常一轮用本轮开始时刻。如果一轮跨过 02:00，紧接着又因换规则而重派生，会把仍可能修订的那一天当作已收盘，持续几秒，直到紧随其后的那一轮修正。
- **O1 的取数量**：
  - 每天约 36 份已收盘日快照中，有 27 份是一小时前被 v1 清理掉、又要重取的日期；
  - BRK 永久缺少的某一种快照，每小时会在每个已收盘日上各问一次（≤ 9 次/小时）；
  - C 的第一份快照如果持续返回 500，会挡住这一步后面的取数，网格降级为 `urpd_grid_partial`；
  - 长期取不到 D 时，已收盘日的快照要等 D 恢复后才会被清理。
- **O3**：
  - 整小时缺失之后的那一行，会同时报 `hour_gap` 和 `intraday_legs`；
  - <1h 供应为 null 时，O3 输出一个标 gap 的 null 点，v1 则不出这个点；
  - 卖压载荷从 577 KB 增到 883 KB。
- **永续 O6**：采集初期 `collecting` 为真，同时更早的块可能已被判定。界面会显示已判定的块和表 1，横幅只作提示。
- **回滚**：P5 的载荷有新字段，旧代码会因 `extra="forbid"` 读不了，直到下一轮派生覆盖（见 RELEASING.md）。
